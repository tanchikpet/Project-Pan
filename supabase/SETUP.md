# Подключение аккаунтов и облачной коллекции

Код настроен на проект `kguiywzypldlxrrayyrg`. Используются только публичные Project URL и Publishable key. Пароль базы, Secret key и `service_role` сайту не нужны.

## 1. Создать таблицу и правила доступа

Открой [SQL Editor проекта](https://supabase.com/dashboard/project/kguiywzypldlxrrayyrg/sql/new).
Создай новый запрос (**New query**), вставь **весь** текст файла [schema.sql](schema.sql) и нажми **Run**. Дождись успешного выполнения. SQL можно выполнить повторно.

Появятся таблица `pan_collections`, правила RLS и две функции: сохранение своей коллекции с проверкой версии и удаление своего аккаунта. Один аккаунт хранит одну коллекцию из трёх разделов. Это первая версия схемы; отдельные таблицы средств и фотографий пока не создаются.

## 2. Настроить ссылки писем

В Supabase открой **Authentication → URL Configuration**.

- **Site URL:** `https://tanchikpet.github.io/Project-Pan/`
- Добавь тот же адрес в **Redirect URLs** и сохрани.

В **Authentication → Sign In / Providers → Email** оставь вход по почте, регистрацию и подтверждение адреса включёнными. При регистрации приложение попросит пароль минимум из восьми символов. При восстановлении ссылка вернёт пользователя на сайт и покажет ввод нового пароля. Открывай ссылку в том же браузере, в котором начата регистрация или смена пароля: используется PKCE.

Для регистрации всех пользователей настрой отправку писем через собственный SMTP в настройках Authentication. Встроенная отправка Supabase предназначена для тестирования, ограничивает частоту и получателей; без SMTP публичная регистрация может не отправлять письма людям вне команды проекта.

## 3. Принять изменения сайта

Прими pull request с аккаунтами в `main`. GitHub Pages опубликует файлы сайта. Без SQL из шага 1 вход может работать, но коллекция не будет синхронизироваться; интерфейс покажет, что база ещё не настроена. Этот код сам не создаёт таблицы в удалённой базе.

## 4. Войти и перенести свою коллекцию

Открой сайт → **Войти / Зарегистрироваться** → **Создать аккаунт**. Подтверди адрес по письму и войди.

Если в браузере есть коллекция предыдущей версии, она сохранится как отдельная локальная коллекция. После входа нажми **Мой аккаунт → Перенести локальную коллекцию в аккаунт**. Перенос выполняется только после подтверждения и заменяет текущую коллекцию аккаунта. Перед заменой можно скачать копию JSON. При большом количестве средств проверь их число после переноса.

Новые пользователи начинают с приветственного экрана: можно добавить средство вручную или войти в свой аккаунт. Встроенные записи автора больше не загружаются всем. Если ты не сохраняла изменения в старой версии, перенеси свою таблицу через **Настройки → Перенести из таблицы**. Укажи раздел и выбери CSV; там же доступны шаблоны столбцов. Старый ключ локального хранения не удаляется автоматически.

Сохранение и восстановление отдельных файлов находится в **Настройки → Резервная копия**. Это дополнительная возможность, а не часть регистрации или обычной синхронизации. Формат резервной копии остаётся JSON, но пользователю не нужно вручную разбирать или редактировать этот файл.

## Что синхронизируется

Каталог косметики, ухода за лицом и телом, архив, причины и даты списания. Отдельные фото, рутины и новые сущности этим изменением не добавлены. Публикация на GitHub Pages остаётся прежней.

Сохранение сначала записывает данные на устройство, затем отправляет в аккаунт. Другой открытый сайт проверяет облако при возвращении на вкладку, подключении интернета и каждые 30 секунд, пока вкладка видна. Кнопка **Синхронизировать сейчас** запускает проверку вручную.

Если устройства изменили одну коллекцию независимо, приложение показывает выбор версии и предлагает сначала скачать текущую. Автоматического слияния отдельных полей пока нет. Обновление с устаревшей ревизией отклоняется самой базой, а не только интерфейсом.

В открытом приложении изменения можно сохранять без сети. Полноценная офлайн-загрузка страницы с нуля пока не реализована (это ещё не PWA). Для загрузки библиотеки Supabase при первом открытии и входа нужен интернет.

На каждом устройстве остаётся локальная копия. Выход скрывает коллекцию аккаунта и показывает отдельную гостевую коллекцию; он не удаляет кеш аккаунта, чтобы не потерять несинхронизированные записи. Очистка данных браузера удалит этот кеш. На общем устройстве после синхронизации и выхода можно очистить данные сайта.

**Удалить аккаунт и облачные данные** удаляет только текущего пользователя и его коллекцию; требует ввода «УДАЛИТЬ». Кеш текущего аккаунта на этом устройстве удаляется. Гостевая коллекция и копии на других устройствах не стираются удалённо.

## Проверка перед публичным запуском

Проверь на двух своих тестовых аккаунтах: регистрация и подтверждение, вход, восстановление пароля, перенос, изменение даты архива, появление данных на другом устройстве, выход и пустая коллекция второго аккаунта. Затем проверь доставку писем через настроенный SMTP. Настоящий Safari на iPhone и удалённая база должны быть проверены после выполнения SQL.

Автоматические проверки: `npm --prefix tests install && npm --prefix tests test` проверяет SQL в локальном PostgreSQL-движке PGlite. `python tests/cloud-ui.test.py` проверяет интерфейс с двумя устройствами и тестовым адаптером SDK (нужны Python Playwright и Chromium; путь можно задать в `CHROMIUM_PATH`). Эти тесты не создают настоящие аккаунты, не отправляют письма и не выполняют SQL в твоём облачном проекте.
